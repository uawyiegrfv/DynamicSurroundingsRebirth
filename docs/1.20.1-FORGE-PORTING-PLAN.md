## 〇、先回答三个决策问题

### Q1 参考哪个源码？——**以当前 26.1 移植版为主，1.12.2 原版为辅**

**主参考 = 当前 26.1 移植版（本仓库 master）。理由：**

1. **功能面 100% 对齐你的需求**：26.1 版的功能是逐项实测确认过的；1.12.2 原版里你明确
   不要的功能（语音气泡、战斗音乐、喷泉、箭矢尾迹、药水图标、水悬浮粒子、后台静音）
   都在原版里，照原版全搬等于搬回你不要的东西。
2. **数据资产全部现成且版本无关**：106 条声音映射、sound_factories/biomes/dimensions JSON、
   sounds.json（900+ 音频文件）、shader、纹理——这是工程量最大的部分，1.20.1 直接复制。
3. **内部架构是自研的、跨版本稳定**：DI 容器（ContainerManager）、ClientState 相位事件、
   数据加载（codec）、配置框架（lib/、config/ 大部分是纯逻辑，改动最小）。
4. **踩坑知识已编码进文档**：MIGRATION_STATUS.md + docs/ 四篇，每个模块移植前先读对应
   章节，就能避开 26.1 趟过的所有坑。

**辅参考 = 1.12.2 原版源码。用途有二：**

1. **功能完整性核对清单**：1.12.2 的包结构（registry/acoustics、client/handlers/fog、
   weather/tracker、speech 等）就是"功能全景图"。用它交叉核对 26.1 版有没有漏功能
   （26.1 版是从阉割版起步、后期缝补起来的，不能只信它自己）。
2. **老 API 的"中间态"实现**：1.20.1 与 1.12.2 同属老 API 世代——粒子
   （TextureSheetParticle）、雾（mixin FogRenderer）、GUI overlay（RenderGameOverlayEvent）、
   渲染（立即模式）。**26.1 重构最狠的模块（粒子/雾/GUI/极光渲染），1.12.2 的旧实现
   比 26.1 的新实现更接近 1.20.1**，直接抄 1.12.2 的写法能大幅加速。

### Q2 1.20.1 官方 fabric 版要不要参考？——**仅作 API 对照，不作为功能来源**

- 功能上它是阉割版（0.3.3 = 0.4.2 的 1.20.1 分支），功能 ⊂ 当前 26.1 版 ⊂ 你的需求，**没有
  可补的功能**。
- 但它有独特价值：它是 **DS 代码在 1.20.1 API 下的实际样子**。粒子/渲染/GUI/雾这些
  "26.1 太新、1.12.2 太老"的中间 API，查它的 common/ 实现最快得到答案。
- 本地只有 1.21.1 分支（0.4.2），**1.20.1 分支需从 GitHub 拉**：
  `git clone -b MC/fabric/1.20.1 https://github.com/OreCruncher/DynamicSurroundingsFabric.git`
- 优先级：26.1 版 > 1.12.2 源码 > 1.20.1 fabric 分支（只查 API 不抄功能）。

### Q3 如何避免三个历史问题？

| 历史问题 | 根因 | 对策（本计划内置） |
|---|---|---|

## 二、1.20.1 关键 API 映射（26.1 → 1.20.1，移植前逐项 javap 验证）

> **javap 是唯一权威**（26.1 教训：凭记忆正则替换产生 200+ 编译错误）。
> 1.20.1 jar 反编译后 grep 目标类确认签名。

| 26.1（NeoForge） | 1.20.1（Forge 47.x） | 影响范围 |
|---|---|---|
| `RegisterGuiLayersEvent` + `VanillaGuiLayers`（层注册系统） | **不存在**。用 `RenderGuiOverlayEvent`（Forge 事件，ElementType 前/后）+ 中间层插入用 mixin `Gui.render` | 全部 overlay（B12/B14/音量浮层/沙尘滤镜） |
| `ViewportEvent.RenderFog` + `FogData` record | **不存在**。mixin `FogRenderer.setupFog(Camera, FogType, float, boolean)`（参考 1.12.2 FogHandler）+ `EntityViewRenderEvent.FogColors` | 雾系统 B11 |
| `SingleQuadParticle` + `Layer` record | `TextureSheetParticle` + `ParticleRenderType` + `ParticleEngine`（spriteSets 直接访问） | 全部粒子 B2-B9（9 个类） |
| `GuiGraphicsExtractor` / extractRenderState 模型 | `GuiGraphics` 立即模式（drawString/fill/blit 直接可用） | GUI 全部 |
| `RenderType.create` + `RenderSetup` | 老式 `RenderType`（RenderStateShard）/ Tessellator 立即模式 | 极光 B1、暴击词 B9 |
| `RegisterRenderPipelinesEvent`（modBus） | 无 framegraph，老式管线 | 极光 B1 |
| `SoundEngine.play()` → `PlayResult` | `play()` → void | A1 mixin |
| `getOverworldClockTime()` | `Level.getDayTime()`（long，%24000） | 时间相关全部 |
| `typeHolder()` | `getBlock()`/直接返回 | 方块获取 |
| `Registry` 新命名（identifier()） | `location()`/getRegistryName() | 注册表访问 |
| `TagsUpdatedEvent.ClientPacketReceived` | `TagsUpdatedEvent`（Forge 有） | tag 同步 |
| `ParticleResources.spriteSets`（@Accessor） | `ParticleEngine.spriteSets`（直接） | 粒子 B2-B9 |
| `modBus`（IModBusEvent） | `modEventBus`（FML 构造器） | 注册 |
| NeoForge moddev 插件 | **ForgeGradle 6.0**（reobfJar、mixin refmap 配置） | 构建脚本整体重写 |
| NeoForge jarJar | Forge jarJar（FG6，META-INF/jarjar）——**1.20.1 loader 支持需验证** | Nashorn D6 |
| Cloth Config 15.x | Cloth Config 11.x（forge 版） | 配置 D1 |
| SereneSeasons 26.1.x | SereneSeasons 8.x（forge）——API 需 javap 核对 | D3 |
| Minecraft 26.1.2（Java 21/25） | Minecraft 1.20.1（**Java 17**） | 工具链 |
| `atlases/particles.json` 覆盖 | 1.20.1 也支持 atlas JSON（1.20 引入）——需验证 | 粒子纹理 |

## 三、阶段计划

### 阶段 0：工具链与地基（1-2 天）

1. **仓库形态**：在 26.1 仓库开 `forge-1.20.1` 分支（共享 git 历史，可随时 diff 26.1 版对照
   "这个功能在 26.1 的表现"；回滚容易）。`master` 保持可运行。
2. **构建脚本重写**：ForgeGradle 6.0 + Gradle 8.x + Java 17；mixin 插件（refmap 生成、
   reobfJar）；mods.toml 按 1.20.1 格式重写（26.1 是 neoforge.mods.toml）。
3. **依赖落地**：Cloth Config 11.x forge、SereneSeasons 8.x forge（libs/ 或 maven）、
   Nashorn 15.4（jarJar 验证，见风险 R5）。
4. **最小编译跑通**：功能模块先 .disabled，只保留版本无关层（lib/ DI/事件/日志/资源/数学/
   随机 + 空 Client），**编译 + runClient 启动 + mixin 加载验证**（dsurround.mixins.json
   放 jar 根，FML 自动发现——1.20.1 无 @Mod mixinConfig 属性，确认加载方式）。
5. **数据加载层**：dsconfigs JSON codec 反序列化跑通（/dsreload 可热重载）。

### 阶段 1：API 摸底（0.5-1 天）

1. 按 §二 映射表逐项 javap 1.20.1 jar / 反编译确认签名，补全映射表细节。
2. 拉取 1.20.1 fabric 分支源码做 API 对照（放仓库外路径）。
3. 核对数据文件中的方块/群系 ID（1.20.1 vs 26.1 差异：1.20.1 无 1.20.2+ 新方块；
   chain→iron_chain 1.20.1 已是铁链；deep_dark 存在）。
4. 产出 `docs/1.20.1-API-MAP.md`（映射表最终版）+ `docs/1.20.1-FEATURE-CHECKLIST.md`（功能清单）。

## 五、测试与验证策略

1. **行为对照实验**：任何"这个功能应该是什么表现"的疑问，切回 master（26.1）实测对照——
   26.1 版是行为基准（遮挡系统方向性 bug 就是用 diff 原版源码定位的，1.20.1 版同理）。
2. **每批冒烟**：runClient + 日志验证（enableDebugLogging、traceMask）→ 你实测。
3. **声音类问题**：先分离开关（occlusion/reverb 独立开关）定位，再对照实验。
4. **发布前启动器实测**（R5 相关，runClient ≠ 发布 jar）。
5. **长时稳定性**：挂机 1h+，验证换世界状态复位、连接/断开事件（ClientState 的
   ON_DISCONNECT 必发保证）。
