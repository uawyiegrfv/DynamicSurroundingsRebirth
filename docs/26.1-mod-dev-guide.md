## 1. 渲染管线（extractRenderState 模型）

26.1 引入"提取渲染状态"架构：CPU 侧 `extractRenderState(...)` 把数据提交到 render state，GPU 侧统一渲染。**旧的 Blaze3D 立即模式（`RenderSystem.setShaderTexture`/`setShader`/`Tesselator`/`BufferUploader.drawWithShader`）全部删除**。

| 旧 (1.21.x) | 新 (26.1) |
|---|---|
| `GuiGraphics`（类） | `GuiGraphicsExtractor`（类删除，新类） |
| `Screen.render()` / `Widget.render()` | `extractRenderState(GuiGraphicsExtractor, x, y, partialTicks)` |
| `AbstractWidget.renderWidget()` | `extractWidgetRenderState()`（final；自定义按钮覆盖抽象钩子 `extractContents()`） |
| 背景 `renderTransparentBackground/renderMenuBackground` | 框架自动调 `extractBackground`，Screen 不再画背景 |
| 列表项 `render(GuiGraphics, index, rowTop, rowLeft, rowWidth, rowHeight, ...)` | `extractContent(GuiGraphicsExtractor, mouseX, mouseY, hovered, partialTicks)`，位置从 `LayoutElement.getX/getY/getWidth/getHeight` 取 |
| `drawString/drawCenteredString/renderTooltip` | `text()/centeredText()/setTooltipForNextFrame()` |
| `blitSprite(Identifier, x, y, w, h)` | `blitSprite(RenderPipelines.GUI_TEXTURED, Identifier, x, y, w, h)`（9 参版顺序 spriteWidth,spriteHeight,textureX,textureY,x,y,w,h） |
| `keyPressed(int,int,int)` / `charTyped(char,int)` | `keyPressed(KeyEvent)` / `charTyped(CharacterEvent)`（事件对象化；`MouseButtonEvent` 同理） |
| `ToastComponent` | `ToastManager`（`Minecraft.getToasts()` → `getToastManager()`） |
| `Toast.render(GuiGraphics, ToastComponent, long)` | `Toast.extractRenderState(GuiGraphicsExtractor, Font, long)` + `update(ToastManager, long)` |
| `AbstractSelectionList.getScrollbarPosition()` | `scrollBarX()` |
| `AbstractSelectionList.ensureVisible()` | `scrollToEntry()` |
| `Music.getEvent()` | `Music.sound()`（record） |
| `SoundManager.getDebugString()` | `getChannelDebugString()` |

**KeyMapping**：`KeyMapping(String, int, String category)` → `KeyMapping(String, int, KeyMapping.Category)`；自定义分类 `KeyMapping.Category.register(Identifier)`，label 取 `key.category.<ns>.<path>`。

**GUI 层注册**：NeoForge `RegisterGuiLayersEvent`，`event.registerBelowAll(Identifier, guiLayer)`；`GuiLayer` 是函数接口 `render(GuiGraphicsExtractor, DeltaTracker)`。层级相对 `VanillaGuiLayers` 的 id。

## 2. 粒子系统（SingleQuadParticle 模型）

粒子管线完全重构。**`TextureSheetParticle` 类删除**，改用 `SingleQuadParticle`。

### 2.1 核心 API 变化

| 旧 (1.21.x) | 新 (26.1) |
|---|---|
| `TextureSheetParticle`（基类） | `SingleQuadParticle`（构造器收 `TextureAtlasSprite`，`sprites.first()`/`SpriteSet.get(rand)` 取） |
| `Particle.getRenderType()` | `getGroup()`（返回 record `ParticleRenderType`：`SINGLE_QUADS/ITEM_PICKUP/ELDER_GUARDIANS/NO_RENDER`） |
| `Particle.render(VertexConsumer, Camera, float)` | `SingleQuadParticle.extract(QuadParticleRenderState, Camera, float)`，quad 经 `extractRotatedQuad(state, camera, Quaternionf, partialTick)` 提交 |
| `ParticleRenderType.PARTICLE_SHEET_TRANSLUCENT` 等 | `SingleQuadParticle.Layer`（`OPAQUE`/`TRANSLUCENT`/`OPAQUE_TERRAIN`/`TRANSLUCENT_TERRAIN`/`OPAQUE_ITEMS`/`TRANSLUCENT_ITEMS`，record `(translucent, textureAtlasLocation, RenderPipeline)`） |
| `Particle.getLightColor(float)` | `getLightCoords(float)`；辉光用 `LightCoordsUtil.addSmoothBlockEmission(int, float)` |
| `ParticleEngine.spriteSets` | 移入 `ParticleResources.spriteSets`（mixin `@Accessor`） |
| 自定义 `ParticleRenderType`（自定义 GL 状态） | 已不可能——`ParticleRenderType` 是 record，自定义渲染靠自定义 `Layer` |
| `ParticleRenderCollection`（批量自定义渲染） | 已不可能——粒子各自 `extract()`，Layer/pipeline 统一管理 |

### 2.2 关键坑（全部实测踩过）

1. **纹理必须显式进粒子图集**：放 `assets/<ns>/textures/particle/`（单数）靠 vanilla 目录扫描**不保证生效**。可靠做法是覆盖 `assets/minecraft/atlases/particles.json`：
   ```json
   { "sources": [
     { "type": "minecraft:directory", "prefix": "", "source": "particle" },
     { "type": "minecraft:single", "resource": "dsurround:particles/pixel_ripples", "sprite": "dsurround:particle/pixel_ripples" }
   ]}
   ```
   然后 `atlas.getSprite(Identifier)` 取（`ParticleUtils.getSprite` 模式）。

2. **`Mth.lerp(delta, start, end)` 参数顺序**：第一参是插值系数！写 `lerp(start, end, delta)` 会静默算出错误 UV。帧 UV 重映射应写 `Mth.lerp(frameUV, sprite.getU0(), sprite.getU1())`。

3. **粒子管线默认背面剔除**：`RenderPipeline.Builder#cull` 默认 `true`。水平铺地的 quad 用 `rotationX(-Mth.HALF_PI)`（法线朝上）；`+90°` 法线朝下从上方看被剔除（vanilla `WEATHER_SNIPPET` 才显式 `.withCull(false)`）。

4. **`particle.fsh` 会 `discard` 透明像素**：`if (color.a < 0.1) discard;`。如果 quad 的 UV 采到纹理透明区（或帧只有寥寥几个不透明像素），整个粒子被丢弃——CPU 日志显示"被渲染且参数正常"但不可见。排查只能靠对照实验（完整 UV vs 帧 UV）。

5. **`getQuadSize` 别从 0 增长**：初始尺寸 0 的粒子出生头几帧不可见。固定 quad 尺寸，环/形状靠帧动画在 quad 内扩张。

6. **SpriteSet 获取**：`ParticleEngine.spriteSets` 移到 `ParticleResources`。需要两个 mixin 访问器：`ParticleEngine.resourceManager` → `ParticleResources.spriteSets`。

7. **粒子 fsh 用 `texCoord0` 采样**，顶点 UV 由 `getU0/getU1/getV0/getV1`（可 override）提供。

## 3. 声音系统 / OpenAL

### 3.1 核心 API 变化

| 旧 (1.21.x) | 新 (26.1) |
|---|---|
| `SoundEngine.play()` 返回 `void` | 返回 `PlayResult`；可取消注入返回 `PlayResult.NOT_STARTED` |
| `Library.init` | 增加 `DeviceList` 参数；属性缓冲移到 `createAttributes()` |
| `SoundEvent.range/newSystem` 字段 | `fixedRange` |
| `SoundEvent.getLocation()` | `location()` |
| `SoundInstance.getLocation()` | `getIdentifier()` |

### 3.2 混响（增强音效）经验

- **OpenAL Soft 版本差异**：26.1 捆绑 1.25.1 默认只给 **2 个辅助发送**（1.21.1 跑 1.23.1 是 4 个）。发送数不足时 `AL_INVALID_VALUE` → 长混响区失效 → 听感"没混响"。
- **强制 4 发送**：mixin `@Redirect` 重写 `alcCreateContext`，属性追加 `ALC_MAX_AUXILIARY_SENDS=4`（LWJGL 第一参是 **long 设备句柄**）。
- **自适应**：`getMaxAuxSends()` 存设备上限；只初始化可用发送；多混响区按能量排序映射到可用发送。
- 诊断日志用 debug 级（限频），勿每声音打。

## 4. 雾系统

26.1 **`FogRenderer` 类移动并重构**（`net.minecraft.client.renderer.fog`）。

### 4.1 API 变化

| 旧 (1.21.x) | 新 (26.1) |
|---|---|
| `FogRenderer`（类） | `net.minecraft.client.renderer.fog.FogRenderer`，`setupFog` 返回 `FogData` 存入 `CameraRenderState.fogData` |
| `FogData.start/end/shape/mode` | `FogData.environmentalStart/End`、`renderDistanceStart/End`、`skyEnd`、`cloudEnd`、`color`（UBO 提交） |
| `MixinFogRenderer` + 自定义事件 | **原生 `ViewportEvent.RenderFog`**（事件带可变 `FogData`，`getType()` 返回 `FogType`，`getPartialTick()` double） |
| `RenderSystem.setShaderFogStart/End/Shape` | 改写 `fogData.renderDistanceStart/End`（在事件 handler 里） |
| `GameRenderer.getRenderDistance()` | `options.getEffectiveRenderDistance()` |
| `Level.getTimeOfDay(1F)` | `getOverworldClockTime()` |

### 4.2 关键坑

1. **主世界 `environmentalStart` 恒为 0**（overworld 维度类型未配 `FOG_START_DISTANCE`），用它做乘法会归零。地形雾对应 26.1 的 **`renderDistanceStart/End`**。
2. **shader 组合**：`total_fog = max(environmental_fog, renderDistance_fog)`。改 renderDistance 影响"远景淡出"。
3. **雾计算器校验**：`start > end || start < 0` 判非法——主世界 environmental 下雨时为负（`RAIN_FOG_START_OFFSET=-160`），旧实现必触发。
4. 距离：DS 雾基于 renderDistance（16chunks=256）会把雾推到 150-230 块，需手动 cap（雨雾 96、晨雾 128）。

## 5. 时间与昼夜

- **`Level.getTimeOfDay` / `getDayTime` / `getMoonBrightness` 删除**，改用 `Level.getOverworldClockTime()`。
- **`getOverworldClockTime()` 返回跨天累计总刻度**（`ClockManager.getTotalTicks`），取日相位必须 `% 24000`。
- **tick 0 = 日出 6AM**（实测 `/time set 18000` 是夜晚）。DS 的角度约定是 **0=正午**，所以日相位角度要 `((ticks % 24000 + 18000) % 24000) / 24000 * 360`（-6h 偏移）。漏偏移会导致白天误判夜晚、晨雾落在午夜。
- `MinecraftClock` 的 `hour = time/1000 + 6` 在 tick0=6AM 下正确。
- `DayCycle.getMoonSize` 简化返回 1.0（`getMoonBrightness` 移除）。

## 7. 调试技巧

1. **javap 是权威**：改 API 前先 `javap -cp minecraft.jar <class>` 确认签名（勿凭记忆/猜测正则替换）。
2. **反编译源码**：`mergeWithSources_*_output.jar` 有完整 `.java`，比字节码易读。
3. **粒子"不可见"先查 discard**：`particle.fsh` 的 `alpha<0.1 discard` 在 GPU 侧，CPU 日志看不出。用对照实验（完整 UV vs 帧 UV、billboard vs 水平）二分定位。
4. **日志会刷屏**：雨滴粒子/每帧 fog 的 debug 日志可让日志文件涨到 GB 级卡死游戏。调试日志必须限频（每 N 帧/次）或及时移除。
5. **图集 sprite 检查**：`atlas.getTextures()` 列全部 sprite；`sprite.transparency()` 判断 OPAQUE/TRANSLUCENT。
6. **渲染顺序/深度**：透明粒子若被水面等遮挡，尝试把 y 略微上浮（深度更近）。
